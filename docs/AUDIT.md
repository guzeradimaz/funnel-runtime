# Аудит соответствия ТЗ

Перед сдачей проект прошёл мультиагентный аудит (Claude Code Workflow, 55 агентов).

**Как проверяли.**
- 7 агентов-аудиторов, по одному на раздел [TASK.md](../TASK.md), работали независимо. Каждый читал код, поднимал свой локальный сервер, гонял API и headless Chrome и проверял публичный стенд https://funnel.guzerchuk.site (только на чтение).
- Каждое расхождение и каждую найденную проблему отдельно перепроверял агент-скептик. Его задача — опровергнуть находку.
- Ниже только то, что скептики подтвердили, с уровнем серьёзности после перепроверки.

## Исправлено по итогам аудита

1. **Доли веток больше 100%.** Если пользователь вернулся назад и сменил ветку, сессия засчитывалась в обе. Теперь засчитывается последний переход с шага (`src/server/analytics.ts`); добавлен тест.
2. **A/B в режиме «Все версии»** склеивал разные версии в одну выборку. Теперь A/B считается только внутри выбранной версии.
3. **Неполный набор UTM в событиях.** `utm_content` и `utm_term` хранились только в сессии. Добавлена миграция 2: колонки в `events` и заполнение старых строк. Она применяется автоматически при старте; на публичном стенде обновление прошло без ручных действий и без потери данных. Добавлен тест `tests/migrations.test.ts`.
4. **`?publish=0` тоже публиковал**, а публикация без `version` отвечала `Version NaN not found`. Теперь публикация срабатывает только на `?publish=1`, а без версии сервер отвечает 400 с понятным текстом.
5. **Воронка по умолчанию** определялась по алфавиту `funnelId`, поэтому загрузка другой воронки могла подменить `/`. Теперь по умолчанию открывается самая ранняя воронка.
6. **Трекер выбрасывал пачку при 408 и 429.** Теперь эти ответы, как и 5xx, считаются временными: пачка отправляется повторно с теми же `event_id`.
7. **Устаревшие мелочи в README**: число тестов, описание демо.
8. **Браузерная проверка теперь в репозитории**: `npm run e2e` (`scripts/e2e.mjs`), работает с любой активной версией.

## Принятые допущения (подтверждены, оставлены сознательно)

- **§3: B — пакетный тест.** Порядок вопросов, копирайт и подпись CTA меняются вместе. Это ограничение дизайна эксперимента, а не реализации; оно описано в README вместе с guardrail «дошли до результата», который от текста CTA не зависит.
- **§8 и §9: таймлайн и агентский процесс подтверждаются в основном текстом README.** Конфиг v3 был известен с начала работы, отдельной ветки второй итерации в git нет. Процесс подтверждают коммиты исправлений после ревью и аудита, тесты, `scripts/e2e.mjs` и этот отчёт.
- **Интерфейс воронки на английском**, как и тексты конфигов. Внутренние страницы на русском.
- **Сервер проверяет только имена свойств события**, а не их значения и обязательность. Сырые ответы этим не пропускаются.
- **Подпись кнопки на вопросах всегда «Continue».** `primaryActionLabel` из конфига используется на info-шагах.
- **Поля `loadingTitle`, `errorTitle`, `retryLabel`** не используются: результат считается синхронно.
- **`cta.action` пишется в событие**, а кнопка всегда раскрывает рекомендации: в конфигах есть только `expand_recommendation`.
- **События для истёкшей сессии принимаются**, если сессия существует. TTL ограничивает только продолжение воронки.
- **Внутренние страницы на демо-стенде открыты без токена** — по просьбе заказчика, для удобства проверки.
